# Жильберта

Локальный ИИ-агент на [Ollama](https://ollama.com/) с внутренней моделью мышления: он хранит долгосрочные факты о пользователе, формирует и сохраняет собственные мнения по темам, периодически рефлексирует над диалогом и связывает темы между собой по смыслу. Всё работает локально, без внешних API — модель крутится через Ollama, данные лежат в JSON-файлах на диске.

## Что умеет

- **Память** — запоминает диалог и извлекает из него долгосрочные факты о пользователе (имя, увлечения, привычки и т.п.), игнорируя разовые реплики. Работает в обоих интерфейсах на каждом сообщении.
- **Убеждения** — по команде `/teach` изучает тему, формирует мнение и сохраняет его в базу знаний; мнение можно пересмотреть командой `/reflect`. Мнения формируются самой моделью (это её точка зрения, а не проверенные факты) и не проверяются через интернет — раздел «Ограничения» ниже.
- **Рефлексия** — каждые `REFLECTION_INTERVAL` сообщений анализирует последние реплики диалога и генерирует короткую внутреннюю мысль. Работает в обоих интерфейсах.
- **Любопытство** — в тот же момент может предложить тему для изучения, если она часто всплывает в разговоре. Работает в обоих интерфейсах.
- **Конфликты мнений** — сравнивает свежие реплики пользователя с уже сохранёнными убеждениями через эмбеддинги; если находит явное расхождение, аккуратно поднимает эту тему в ответе.
- **Ассоциации** — связывает темы друг с другом по общим тегам и иногда неожиданно вспоминает смежную тему посреди разговора.
- **Streamlit UI** — веб-интерфейс с окном чата и панелью отладки, показывающей текущий фокус, убеждения, мысли и полный системный промпт.

## Два интерфейса, одна память

CLI (`chat.py`) и Streamlit (`app.py`) работают с одними и теми же файлами в `data/` и вызывают один и тот же движок (`core/chat_engine.process_message`). Это значит:

- Память, извлечение фактов о пользователе, рефлексия, любопытство и определение конфликтов работают **одинаково в обоих интерфейсах** — не только в CLI.
- Единственное реальное отличие: **слэш-команды** (`/teach`, `/approve`, `/reject`, `/reflect`, `/knowledge`, `/brain`, `/stats`) доступны только в CLI. В Streamlit нет ввода команд — только обычный диалог и панель отладки для просмотра уже накопленного состояния.

Если хотите специально «обучить» Жильберту какой-то теме через `/teach` + `/approve` — это делается только в CLI. Открытый после этого `app.py` увидит те же знания, потому что читает те же файлы.

## Ограничения (осознанно, не баги)

- Изучение темы через `/teach` не ходит в интернет и не проверяет факты — это собственное «мнение» модели по теме, сформированное из её обучающих данных. Директория `tools/` зарезервирована под внешние инструменты (например, поиск в интернете), но сейчас пуста — ничего из внешнего мира агент не подтягивает.
- Извлечённые факты о пользователе сохраняются автоматически, без подтверждения (в отличие от `/teach`, где есть `/approve`/`/reject`). Если модель ошибочно извлечёт факт — он попадёт в профиль и будет использоваться в последующих ответах. Отдельной команды для удаления одного факта нет; полный сброс — см. раздел «Данные».
- Раз в `REFLECTION_INTERVAL` сообщений список фактов профиля целиком переписывается моделью (`consolidate_facts`), чтобы убрать дубли и противоречия. У фактов профиля нет истории версий (в отличие от мнений по темам, где хранятся все прошлые версии).
- На сообщении, где срабатывает рефлексия, выполняется несколько последовательных обращений к модели подряд (извлечение факта → генерация ответа → консолидация фактов → рефлексия → любопытство), поэтому такое сообщение обрабатывается заметно дольше обычного — особенно на слабом железе.
- `tests/` — это ручные smoke-скрипты для проверки отдельных модулей, а не автоматические тесты; для их запуска нужна работающая Ollama.

## Требования

- Python 3.10+
- [Ollama](https://ollama.com/), установленный и запущенный

## Установка

1. Установите Ollama и скачайте модель:

   ```bash
   ollama pull qwen3:8b
   ```

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Убедитесь, что Ollama запущена (`ollama serve` или фоновый процесс приложения).

## Запуск

**CLI** — полнофункциональный режим, со всеми командами:

```bash
python chat.py
```

**Streamlit UI** — веб-чат с той же памятью и панелью отладки (без слэш-команд, см. «Два интерфейса, одна память» выше):

```bash
streamlit run app.py
```

## Команды CLI

| Команда | Что делает |
|---|---|
| `/teach <тема>` | Изучить тему: сформировать краткое описание, предварительное мнение и список связанных понятий |
| `/approve` | Сохранить результат последнего `/teach` или `/reflect` в базу знаний |
| `/reject` | Отменить результат последнего `/teach` или `/reflect`, ничего не сохранять |
| `/reflect <тема>` | Пересмотреть текущее мнение по уже изученной теме |
| `/knowledge` | Показать список всех изученных тем |
| `/knowledge <тема>` | Показать описание, текущее мнение и историю мнений по теме |
| `/brain` | Показать профиль пользователя, последние факты и последние размышления |
| `/stats` | Показать статистику: число сообщений, фактов, размышлений |
| `выход` | Завершить диалог (память сохраняется автоматически) |

Любой другой ввод воспринимается как обычная реплика в диалоге.

## Переменные окружения

Задаются через `config.py` / переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MODEL` | `qwen3:8b` | Модель Ollama, используемая для всех запросов |
| `TEMPERATURE` | `0.7` | Температура генерации |
| `MAX_HISTORY` | `30` | Сколько последних сообщений хранить в `data/memory.json` |
| `MAX_LLM_CONTEXT` | `25` | Сколько последних сообщений реально передавать модели как контекст |
| `REFLECTION_INTERVAL` | `25` | Раз во сколько сообщений запускать рефлексию, любопытство и консолидацию фактов |
| `THOUGHT_MAX_LEN` | `180` | Максимальная длина сохраняемой мысли (символов) |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Модель эмбеддингов для семантического поиска по темам |
| `SIMILARITY_THRESHOLD` | `0.35` | Порог косинусной близости для семантического поиска тем |
| `TOP_K_SIMILAR` | `5` | Сколько ближайших тем возвращать при семантическом поиске |

## Структура проекта

```
chat.py                — точка входа CLI
app.py                  — точка входа Streamlit UI
config.py               — настройки (модель, интервалы, пороги)

core/                   — инфраструктура: LLM-клиент, хранение памяти/профиля/знаний,
                          построение системного промпта, единый движок диалога (пайплайн)
brain/                  — LLM-вызовы для конкретных задач: извлечение фактов,
                          рефлексия, любопытство, изучение темы, семантический recall
mind/                   — сборка «текущего состояния» (фокус, убеждения, ассоциации)
                          и его рендер в текст для системного промпта
commands/               — диспетчер и обработчики CLI-команд
prompts/                — статический текст личности Жильберты
tools/                  — зарезервировано под внешние инструменты (сейчас пусто)
tests/                  — ручные smoke-скрипты для проверки отдельных модулей
                          (не автоматические тесты, требуют запущенной Ollama)
```

## Данные

Всё состояние хранится локально в JSON-файлах в `data/` и `memory/` (обе директории создаются автоматически и не попадают в git). Никакие данные никуда не отправляются, кроме локального запроса к Ollama.

Чтобы сбросить память с нуля — удалите содержимое `data/` и `memory/` (или очистите диалог кнопкой в сайдбаре Streamlit — это очистит только `data/memory.json`, база знаний и профиль пользователя останутся).
